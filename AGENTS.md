# go-julep

Unofficial Go client for the Julep API. If you only want to use the client from an agent, read [.agents/skills/go-julep/SKILL.md](.agents/skills/go-julep/SKILL.md) instead; this file is about changing the code.

## Architecture

The client is generated. `make generate` runs `go generate ./...`, which runs the `//go:generate` lines in `gen.go`:

1. `scripts/fetch-spec.sh` reads `openapi_spec_url` from the `.stats.yml` of julep-ai/python-sdk and downloads that URL to `api/openapi.yaml`. Stainless hosts the spec under a content-hashed URL that changes on every update.
2. `go tool oapi-codegen --config=config.yaml api/openapi.yaml` writes the models to `models.gen.go`.
3. `go tool oapi-codegen --config=config.client.yaml api/openapi.yaml` writes `Client` and `ClientWithResponses` to `client.gen.go`.

The output is split in two because a single file runs past 40,000 lines. No patch step is needed; the spec generates as published. If one becomes necessary it goes in `scripts/` and runs between the fetch and the generate steps.

## Stack

- Go 1.26.9, one package `julep` at the module root.
- oapi-codegen v2 as a `go.mod` tool, with `github.com/oapi-codegen/runtime` at runtime.
- Both configs map `number` to `float64`.

## Layout

- `gen.go`: package doc and the generate steps.
- `config.yaml`, `config.client.yaml`: oapi-codegen settings for the two output files.
- `models.gen.go`, `client.gen.go`: generated, never edited by hand.
- `client_test.go`, `example_test.go`: httptest-backed tests and the README example.
- `scripts/`: spec fetch, lint and security scan scripts.
- `api/`: the downloaded spec, gitignored, never committed.
- `vendor/`: committed, regenerated by `make dep`.

## Dev workflow

Everything runs in the `Dockerfile.dev` image. You need Docker and Make.

```bash
make dep       # go mod tidy + go mod vendor
make generate  # download the spec and regenerate
make lint      # shellcheck, shfmt, go fix, golangci-lint
make test      # go test -race
make sec       # gitleaks, govulncheck, semgrep
```

## Project-specific landmines

- The spec URL in `.stats.yml` changes with every upstream spec update, so never hardcode a Stainless URL.
- The spec file is YAML written in JSON style. The dev image has no YAML parser, so `fetch-spec.sh` checks for the `openapi` key with grep.
- The spec's security scheme is a bare `Authorization` header API key, but Julep's SDKs prefix the key with `Bearer `. The README and tests follow the SDKs.
- Method names come from FastAPI-style operation IDs and carry the path and HTTP method (`ListAgentsAgentsGet`). A spec update that changes an operation ID renames the method.
- `scripts/sec.sh` excludes one semgrep rule, the `interface{}` unmarshal check, because oapi-codegen decodes free-form `additionalProperties` that way.
- CI skips the generate drift check, because the spec changes upstream without notice. Regenerate locally and commit the result.
- `.github/workflows/regen.yml` regenerates the client every day and releases the result. When the checks fail, Claude edits the repository to fix them, but a fix may not touch the paths listed under `fix_protected_paths` in that workflow: the workflows, the Makefile, `AGENTS.md`, `.agents/rules/`, the lint, security and spec download scripts and their configs. A problem that needs a change there fails the run and needs a manual fix.
